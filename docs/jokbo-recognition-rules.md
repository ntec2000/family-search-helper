# 족보 인식·인명 구성 규칙

## 목적과 구현 범위

Android와 iPhone·Mac·PC 브라우저에서 같은 파서, 인물 검토, 저장, 내보내기를 사용한다.
원본 이미지는 보존하고 인식용 구획만 별도로 만든다. 웹 OCR은 브라우저에서 실행한다.
현재 전통 한지 색·먹색·붉은 강조색과 기존 서체를 유지하고, 제외 버튼을 인물 카드에 노출한다.
넓은 화면은 최대 폭을 제한해 원문과 인물을 읽기 쉽게 한다. 새 디자인 서비스에 족보를 업로드하지 않는다.

## 공통 해석

1. 가로 구획선은 세대 구획 후보다. 구획 안에서는 오른쪽 열부터 위→아래로 읽는다.
2. 子/男 뒤의 한자는 본손 이름 후보다. 二/三/四 등 차례 표기는 이름과 분리한다.
   字/號/世/配/父/祖/曾祖/外祖/生/卒/忌/墓/出系는 이름에 넣지 않는다.
3. 가문 성씨는 표제의 성씨 또는 사용자가 입력한 성씨를 사용한다. 배우자 성씨로 본손 성을 추측하지 않는다.
4. 女 뒤에 적힌 이름은 사위 후보다. 딸 개인 이름은 만들지 않는다.
   확인된 가문 성이 李이면 화면에는 '이씨 (개인 이름 미상)'로 표시하고 성/이름 필드는 분리한다.
   安東人·全州人만 있으면 남편 이름도 미상이다. 딸의 순서는 원문에 명시된 경우만 확정한다.
5. 配 뒤의 본관·성씨는 배우자 표시다. 父/祖/曾祖/外祖는 배우자 쪽 조상이며 본손 부모 ID로 자동 연결하지 않는다.
   判官·通政은 관직·품계다. 同知가 인명으로 사용되는 첨부 예시는 그대로 보존한다.
   文化柳承春의 文化, 濟州高의 濟州는 본관이다. 원문은 남기고 인명과 구분한다.
6. 간지·음력은 원문 날짜로 보존한다. 서기 연도나 출생지를 생성하지 않는다.
   忌三月五日은 '기일, 연도 미상'이다. 본인과 배우자의 날짜는 配 경계로 구분한다.
7. 出系顯龍后·出系寅東后는 출계 메모로 남긴다. 친부·양부 관계를 자동 확정하거나 삭제하지 않는다.
8. 聖甲/성중처럼 한자와 한글이 다르면 양쪽 표기와 확인 필요 의견을 메모에 남긴다.
9. 이름 아닌 후보는 '인물 아님' 버튼으로 검토 목록에서 제외하고 복원할 수 있다.
   원본 OCR과 이미지는 지우지 않으며 기존 DB 인물을 삭제하는 기능과 구분한다.

## FamilySearch 입력 자료

- 성·이름, 한글·한자 표기, 성별, 출생·사망·매장, 원문 근거, 검토한 부모 관계를 분리한다.
- 본관+성씨, 자/호, 관직은 개인의 출생 이름으로 만들지 않는다.
- 개인 이름 미상 딸은 성만 내보내며 '씨'를 이름에 넣지 않는다.
- 간지와 배우자·처가·출계 기록은 메모로 보존한다. 관계는 사용자가 검토한 ID만 내보낸다.
- FamilySearch 직접 전송은 기존의 별도 로그인·사용자 동의 흐름을 유지한다.

## 검증 및 한계

첨부 224쪽의 수동 전사 정답과 실제 OCR 출력은 분리한다. 전사 파싱 테스트 통과를 OCR 정확도로 보고하지 않는다.
구획 검출, 이름/주석 분류, 날짜 경계, 성씨 보존, 제외/복원, DB 지속성, GEDCOM을 테스트한다.
웹·Android 빌드를 실행하고 브라우저에서 이미지 선택→OCR→검토→저장→재시작→내보내기를 점검한다.
첫 웹 OCR 실행에는 엔진·언어 모델 다운로드가 필요하다. 외부 CDN은 공개 모델 배포용이며 이미지 전송용이 아니다.

## 절대 준수
1. 족보 인물, 한자, 이름, 혈연, 성별, 연대, 양자/출계 정보를 임의 생성하거나 추측해 확정하지 않는다.
2. 원본 이미지 및 OCR 원문을 보존한다. OCR 후보와 사용자 검토/확정 데이터의 구분을 유지한다.
3. 부모·자녀 관계는 사용자 검토로만 확정한다. OCR 배열 순서만으로 관계를 연결하지 않는다.
4. 이름 없는 딸은 임의 작명하지 않는다. 음력 간지 날짜를 임의로 양력 변환하지 않는다.
5. 삭제·제외·복원에서 확정된 관계를 조용히 유실하지 않는다. 저장 전 검증과 오류 안내를 유지한다.
6. 테스트·빌드 실행 결과를 실제 수행 전 성공으로 보고하지 않는다. 작업 브랜치에서 작은 커밋으로 수정한다.

## Codex 최우선 작업
1. 해당 작업 브랜치를 체크아웃하고 `git status`, Flutter/Dart 버전, `pubspec.yaml` 확인.
2. `flutter pub get`, `flutter analyze`, `flutter test`를 실제 실행하고 실패 원인을 수정한다. 가능하면 Android debug APK 빌드까지 수행한다. 실행 불가능하면 환경상 원인을 정확히 보고한다.
3. `ParentChildReview.validateReviewedBatch`에 동일 부모의 `childrenIds` 중복 ID 검증 추가. 기존 중복 **인물 ID** 검사와 혼동하지 않는다.
4. 부친 ID는 남성 부모, 모친 ID는 여성 부모를 가리키는지 명시적으로 검사하고, 성별 미확정·오류 상태를 사용자에게 표시한다. 외부 ID는 검토 배치에 없을 수 있으므로 무조건 잘못으로 처리하지 않는다.
5. 정상 양부모 관계, 중복 자녀 ID, 잘못된 부모 성별, 누락/충돌 역방향 관계에 대한 단위 테스트 추가.
6. 저장 전 오류 대화상자에서 모든 검증 오류를 보여주며, 필요하면 내역 복사 기능 추가.
7. 추가로 검토: `ParentChildReview.unlink`의 `parent.childrenIds.remove(child.id)`는 중복 항목을 하나만 제거하므로 잔존 링크 위험이 있다. `removeWhere`와 회귀 테스트 검토.
8. 저장 시 인물별 `upsertPerson` 순차 호출로 일부만 저장되는 경우가 가능한지 DB 트랜잭션을 조사하고, 안전한 원자적 저장을 검토한다.

## 현재 검증 로직의 한계
- `validateReviewedBatch`는 현재 화면 검토 목록에 포함된 인물의 관계만 확인하며, 외부 데이터베이스 인물 ID는 검증하지 않는다.
- 부모가 자녀를 가리키고 자녀가 부모를 가리키는지 양방향 검사한다.
- 중복 자녀 ID 검증은 아직 없음.
- 저장 실패 상세 안내와 중복 자녀 검증 등은 테스트 실행으로 검증해야 한다.

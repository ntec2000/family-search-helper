# 족보 224쪽 인식·해석 테스트 사례

출처: 사용자가 제공한 족보 224쪽 이미지와 수동 해석. 아래 내용은 OCR 엔진의 자동 인식 성공 결과가 아니라 **검증용 정답 사례**입니다.

## 읽기 규칙
- 세로쓰기: 오른쪽에서 왼쪽, 같은 세로열은 위에서 아래로 읽습니다. 가로 구획선과 오른쪽 세대표기를 함께 확인합니다.
- 子/女/配/父/祖/曾祖/外祖/字/墓/生/卒/忌/出系 등은 인명 자체가 아닙니다.
- 子 다음 한자는 자녀 이름 후보입니다. 고립된 한자 단어는 사람 이름으로 자동 확정하지 않습니다.
- 女만 기재되면 개인 이름은 미상입니다. 아버지의 성을 확인한 경우에만 '이씨'처럼 표시하며 원문 이름이 아님을 기록합니다.
- 配 原州邊氏 등은 배우자의 본관·성씨로, 개인 이름을 창작하지 않습니다.
- 배우자 블록의 父/祖/曾祖/外祖는 배우자 측 친족 정보입니다.
- 干支生/卒은 간지 기록으로 보존합니다. 서기 연도는 추정하지 않습니다.
- 出系는 입양·계통 이동 기록입니다. 원부모 관계를 무조건 삭제하거나 새 친자관계를 자동 생성하지 않습니다.
- 오기 가능성은 원문과 정정 의견을 모두 메모에 남깁니다.

## 검증 범위 및 다음 개발 항목
- 현재 추가된 GenealogyNameClassifier는 단일 OCR 문자열의 보수적 후보 분류만 담당합니다.
- 전체 페이지의 세대별 구조·인물 ID 연결·배우자 계보 파싱·사용자 삭제 버튼은 아직 연결되지 않았습니다.
- 실제 OCR 결과를 이미지 정답과 비교하여 오탐/누락을 측정해야 합니다.
- 사용자 화면에서는 원문, 후보, 인물/설명 분류, 삭제/복원, 확정 저장을 분리해야 합니다. 삭제는 원본 OCR이나 기존 DB 인물을 지우는 기능이 아니라 후보 목록에서 제외하는 방식이어야 합니다.

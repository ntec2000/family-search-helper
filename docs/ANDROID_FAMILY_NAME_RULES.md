# 가족역사 기록 도우미 — Android 우선 인물 추출 규칙

## 고정 작업 방향
Android 앱을 먼저 완성합니다. 공통 Flutter 코드를 유지하되 별도 웹 배포나 iOS 네이티브 작업을 우선하지 않습니다.
Android는 ML Kit, 웹은 Tesseract.js, 선택적인 PC 서버는 RapidOCR를 사용하므로 같은 사진의 OCR 결과가 다를 수 있습니다.

## 이름과 인물 목록
1. 작업 가문의 성씨는 아들·딸에게 적용합니다. 처가·사위·그 가족에게 작업 가문의 성씨를 강제하지 않습니다.
2. 개인 이름을 읽은 본인은 성+이름으로 표시합니다. 字·號·관직·본관을 개인 이름에 섞지 않습니다.
3. 개인 이름 미기재 딸은 아버지 성씨+씨로 표시합니다. 女 뒤 이름은 남편 후보로 분리합니다.
4. 아내의 개인 이름 없이 본관·성씨만 있으면 성씨+씨를 표시합니다. 본관은 별도 보존합니다.
5. 배우자의 부친·조부·증조부는 기록된 배우자 성씨를 조합한 후보를 표시합니다. 외조부는 자체 성씨를 사용합니다.
6. 처가·사위 쪽 남자의 이름이 있고 그 부인 개인 이름이 없으면 남자 성함+의 부인 표시 후보를 함께 만듭니다.
7. 생성 표시명은 generated_name에 저장하고 실제 name_hanja/name_hangul을 비워 둡니다. 실제 이름을 입력하면 그것을 우선 표시합니다.
8. 가족 이름 후보 화면에서 선택한 인물을 기존 검토 목록으로 추가할 수 있습니다. 내용·관계 검토 후 원자적으로 저장합니다. 이름만 같다는 이유로 서로 합치지 않습니다.
9. 딸 순번은 연결된 아버지별 기록 등장 순서로 표시합니다. 실제 출생순서로 새로 확정하지 않습니다.
10. 날짜·출계·관계의 원문을 보존합니다. 부인의 표시명을 생성한 것만으로 생물학적 모자 관계를 자동 확정하지 않습니다.

## 224쪽 샘플 검증
사용자가 제공한 최신 정리본을 샘플의 수동 검수 기준으로 삼습니다. 기존 자동 OCR 결과를 정답으로 취급하지 않습니다.
샘플의 고유 이름을 다른 족보에 강제로 대입하지 않습니다.
원본과 해석이 충돌하면 사용자 판독과 원문을 구분해 보존합니다. 예를 들어 불완전한 간지 날짜나 同知 같은 관직/이름 후보는 추가 검토합니다.
이름 후보를 구성하는 테스트와 실제 사진에서 자동 인식하는 시험은 별개입니다. 테스트 통과를 완전한 OCR 정확도로 보고하지 않습니다.

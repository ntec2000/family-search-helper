# 텍스트 내보내기 인물 순서 수정

- 작업 브랜치: work/jokbo-update-20261024.
- 현상: 분석에서 붙인 딸 순번은 유지되지만, 텍스트 목록이 최근 수정순으로 조회되어 다섯째딸부터 첫째딸까지 거꾸로 보인다.
- 원인: ExportScreen._previewText가 홈 목록과 같은 updated_at DESC 조회를 사용한다.
- 수정: 텍스트 미리보기·복사·공유 자료만 created_at ASC, rowid ASC로 조회한다. 같은 생성 시각이면 DB 삽입 순서를 사용한다. 기본 목록은 기존 최근 수정순을 유지한다.
- 보존: 원문, 성명, 딸 순번, 원문 명시 서수, 날짜, 관계, DB 스키마를 변경하지 않는다. 생성 순서는 실제 출생순서나 부모 관계를 의미하지 않는다.
- 회귀 검증: 실제 SQLite DB를 사용하는 ExportScreen 위젯 테스트. 아들 뒤에 등장한 첫째·둘째딸과 원문 명시 열째딸이 올바른 위치에 출력되는지, 동일 생성 시각과 다른 수정 시각을 처리하는지, DB 내용이 그대로인지 확인한다.
- 수정 전 CI 41257234477: 339개 통과, 신규 회귀 테스트 1개 실패로 역순 출력을 재현했다. 수정 후 결과는 해당 수정 커밋의 GitHub Actions를 확인한다.
- 한계: 과거 기록의 생성 시각과 삽입 순서가 원래 분석 순서를 보존하지 않으면 이 정보만으로 원문 순서를 복원할 수 없다. OCR 한자 정확도는 원본 대조가 별도로 필요하다.
